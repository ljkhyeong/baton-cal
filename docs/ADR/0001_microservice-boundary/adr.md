# ADR-0001: BATON CAL 마이크로서비스 경계

- 상태: 채택됨
- 결정일: 2026-08-11

## 배경

BATON이 시즌 시간대, 반복 일정, 운영 회차와 실제 마감을 결정한다.
캘린더 구독은 주기적 조회·캐시·토큰 폐기·취소 반영을 별도로 처리해야 한다.

## 결정

BATON CAL을 읽기 전용 iCalendar 구독 서비스로 둔다. CAL은 BATON이 확정한 스냅샷을
수신하며 반복 일정이나 마감을 다시 계산하지 않는다.

CAL은 해시된 구독 토큰, 캘린더 피드 투영, 안정적인 `UID`와 `SEQUENCE`, 취소 표식,
조건부 GET과 재구축을 담당한다. 구독 발급 가능 여부와 원본 접근 권한은 BATON이 판단한다.

첫 버전에는 제공자 API를 이용한 양방향 캘린더 동기화를 포함하지 않는다.

## 결과

장점:

- 캘린더 조회 트래픽과 캐시 갱신을 BATON의 일정 변경 처리와 분리한다.
- 토큰 폐기·회전과 캘린더 호환성을 독립적으로 운영할 수 있다.
- 시간 규칙은 BATON에서만 관리한다.

비용:

- 스냅샷 이벤트, 원본 개정 번호와 취소 보존 기간 계약이 필요하다.
- 구독 URL 유출에 대비한 토큰 보호와 요청 수 제한이 필요하다.
- 캘린더 앱마다 갱신 주기가 달라 변경 반영이 늦어질 수 있다.

## 보류한 대안

- BATON 내부 `.ics` 엔드포인트: 초기 구현은 단순하지만 조회 트래픽, 토큰과 캐시 정책이
  BATON 서버에 추가된다.
- Google/Microsoft API 직접 연동: OAuth 자격 증명 관리와 양방향 수정 충돌 처리까지 필요해
  첫 MVP의 구현·운영 범위가 커진다.
