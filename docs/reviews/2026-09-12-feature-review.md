HEAD 개선은 기존 구독 URL과 GET·304·404 동작을 유지한다. DB 스키마나 외부 서비스를 추가하지 않는다.
HEAD 회귀 테스트는 GET과의 헤더 일치, UTF-8 바이트 길이, 조건부 조회 우선순위, 빈 피드,
잘못된 주소·재발급·해제·이전 세대 토큰 차단을 확인한다. 조회 비용은 본문 조회가 호출되지 않는지 검증하며,
응답 속도 개선율은 별도로 측정하지 않는다.

DB 연결 실패 개선은 기존 Spring 예외 분류와 `api-error.v1` 응답을 사용한다. 서버 내부에서 재시도하지 않는다.
실제 연결을 모두 점유해 발급·피드 조회의 `503`을 확인하고, 연결 반환 후 정상 조회·구독 생성과 중복 저장 방지를 검증한다.

구독 생성 개선은 기존 DB 기본키와 트랜잭션을 사용하며 API와 스키마는 유지한다. 신규 요청에는 ID 조회가
한 번 추가된다. 동시 생성, 다른 시즌에 같은 ID를 사용한 요청의 충돌, 캘린더 생성 실패 후 같은 ID의 재시도를 검증한다.

HTTP 캐시는 `404` 같은 실패 결과도 저장할 수 있다. 상태 조회의 오류가 저장되면 자원이 생성된 뒤에도
이전 결과를 재사용할 수 있으므로 공통 상태 오류 처리에서 저장을 금지한다.
[RFC 9111 §2](https://www.rfc-editor.org/rfc/rfc9111.html#section-2),
[§5.2.2.5](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.5).
실제 캐시 장애를 관측한 것은 아니며, 기존 HTTP 테스트에서 헤더와 `404 → 생성 → 200` 흐름을 검증한다.

같은 초의 일정 변경은 기존 계약대로 강한 ETag로 구분한다. 복구 상태 조회는 저장된 완료 기록과 현재
상태 진단을 구분하며 자동으로 복구 모드를 해제하지 않는다. 이 범위에는 새 API나 추가 검증 로직을 넣지 않는다.

`697f2b1`의 후속 점검에서는 추가 구현이 필요한 새 문제를 확인하지 못했다. 미작성 상태였던
[rc.2 릴리스 노트](../releases/contracts-v1.1.0-rc.2.md)를 작성하고 계약 안내에 HEAD와 상태 조회 오류의
캐시 정책을 반영했다. `rc.1`과 비교해 기존 JSON 스키마·골든·DB 마이그레이션의 변경이 없음을 확인했다.
최종 검증 결과는 [인수인계](../../HANDOFF.md)에 기록한다.

## DB 동시 처리 실패 재검토

`81b2e99` 기준으로 일정 수신·구독 생성·회전·폐기·복구와 공통 오류 처리를 확인했다.
기존 처리기는 `CannotAcquireLockException`만 받아 교착 상태·직렬화 실패를 놓쳤다. 운영에서 발생한
장애를 확인한 것은 아니며, 고정한 Spring 7.0.9와 제품의 PostgreSQL 예외 변환기로 두 오류의 `500` 응답을 재현했다.

[Spring이 권장하는 공통 예외](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/dao/PessimisticLockingFailureException.html)
`PessimisticLockingFailureException`으로 처리 범위를 바꿨다. SQLSTATE 직접 분기·의존성·서버 내부 재시도는
추가하지 않았다. 수정 후 두 오류의 `503`, 중복 키·SQL 문법 오류의 `500`, 응답 스키마와 비밀값 비노출을
포함한 관련 테스트 10개가 통과했다. 실제 DB 교착 상태를 만드는 부하 실험은 이번 검증에 포함하지 않았다.

## 정수 입력 재검토

`c2ab304` 기준으로 입력 파싱과 저장 경계를 확인했다. Jackson 3.1.5의
[`ACCEPT_FLOAT_AS_INT`](https://github.com/FasterXML/jackson-databind/blob/jackson-databind-3.1.5/src/main/java/tools/jackson/databind/DeserializationFeature.java)가
기본으로 켜져 있어 기존 문자열 변환 차단 설정과 별개로 소수를 정수로 잘랐다. 실제 HTTP 테스트에서
일정·시즌 이름의 개정 번호, 복구 항목 수·이름 개정 번호·전체 시즌 수의 소수·지수 표기 9건이 `200`을 반환했다.

Spring Boot 설정에서 이 변환을 껐다. 관련 테스트 38개가 통과했으며, 오류 스키마·미저장·정수로 수정한
요청의 정상 처리와 기존 타임스탬프 소수 초·nullable 필드를 확인했다. 사용자 정의 파서·검증기·의존성은 추가하지 않았다.

이 설정은 `1.0`·`1e0`도 거부한다. [JSON Schema의 정수 판정](https://json-schema.org/understanding-json-schema/reference/numeric#integer)과
숫자 표기 조건은 다르므로 PRD·계약 안내·rc.2 릴리스 노트에 별도 명시했다. 정상 정수 입력·응답 구조·DB 스키마는 유지한다.

## 문자열 입력 재검토

`8e2c7fb` 기준으로 문자열 타입의 입력을 확인했다. 기존
[`ALLOW_COERCION_OF_SCALARS`](https://github.com/FasterXML/jackson-databind/blob/jackson-databind-3.1.5/src/main/java/tools/jackson/databind/MapperFeature.java)는
문자열을 제외한다. 제목·설명·장소·시즌 이름에 `123`, `12.5`, `true`를 보낸 HTTP 요청 12건이
기존에는 `200`으로 처리됐다. 스키마가 요구하는 문자열 타입을 위반해도 변환된 값으로 저장되는 문제였다.

`JsonMapperBuilderCustomizer`에서 `LogicalType.Textual`에 대한 숫자·불리언 변환을 차단했다.
관련 테스트 34개가 통과했고, 잘못된 타입의 `400`·오류 스키마·수정한 요청의 정상 처리와 기존 Unicode·
줄바꿈·선택 필드 처리를 확인했다. 문자열의 내용 제약과 DB·응답 스키마는 유지한다.

## 묶음 수신

사용자의 진행 요청에 따라 크기를 제한한 동기식 묶음 수신을 추가했다. 단건과 같은 판정 함수를
사용하며 별도 큐·의존성·DB 스키마는 추가하지 않았다. HTTP 회귀 테스트 11개와 전체 164개 테스트가
통과했다. 단건 대비 100건 묶음의 1,000건 적재·동시 변경 측정은 [성능 기준](../performance-baseline.md)에 기록했다.

테스트 컨텍스트 추가로 공유 PostgreSQL의 연결 한도를 초과한 문제도 확인했다. 테스트 전용
`minimum-idle=0`으로 유휴 연결의 사전 확보를 줄이고 전체 실행을 통과했다. 운영 연결 풀은 유지한다.
공개 `cal.b4ton.com`은 2026-09-12 로컬 네트워크에서 DNS 조회에 실패해 실제 앱 검증을 진행하지 못했다.
