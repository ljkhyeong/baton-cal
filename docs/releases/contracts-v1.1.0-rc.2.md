# BATON CAL 계약 1.1.0-rc.2

게시 전 검토본이다. 아래는 `1.1.0-rc.1` 이후 변경 사항이며, 안정 계약 `1.0.0`은 정식 승격 전까지 유지한다.

## 주요 변경

- 개정 번호와 건수의 소수·지수 표기를 정수로 잘라 받던 동작을 수정했다. `0.5`, `1.0`, `1e0`은
  `400 INVALID_REQUEST`로 거부한다. 소수점·지수 없는 정수로 보내야 하며 타임스탬프의 소수 초는 유지한다.
- 제목·설명·장소·시즌 이름 등 문자열 필드의 숫자·불리언 입력은 `400 INVALID_REQUEST`로 거부한다.
  `"123"`·`"true"` 같은 정상 문자열과 허용된 필드 생략·`null`은 유지한다.
- `PUT /internal/api/v1/subscriptions/{subscriptionId}`로 BATON이 미리 저장한 ID를 사용해 구독을 생성한다.
  최초 성공만 `201`과 토큰을 반환한다. 같은 ID·시즌은 `409 SUBSCRIPTION_ALREADY_EXISTS`,
  다른 시즌은 `409 SUBSCRIPTION_SCOPE_CONFLICT`이며 기존 토큰·상태·세대를 보존한다.
- `GET /internal/api/v1/recovery-runs/{recoveryId}`로 저장된 복구 진행 상태, 검증한 시즌 수,
  최초 완료 시각과 현재 복구 모드를 조회한다.
- `GET /internal/api/v1/seasons/{seasonId}/recovery-state`로 현재 일정 수·다이제스트와
  시즌 이름 개정·다이제스트를 조회한다. 일정과 이름 중 어느 쪽이 복구 기대값과 다른지 비교할 수 있다.
- 공개 HEAD는 본문을 읽지 않고 구독 상태와 GET과 같은 ETag·Last-Modified·파일 크기를 반환한다.
  GET·HEAD의 `Content-Length`는 UTF-8 바이트 수다. 조건부 조회와 무효 토큰 차단은 유지한다.
- DB 연결·트랜잭션 시작 실패와 교착 상태·직렬화 실패도
  `503 SERVICE_BUSY`, `Retry-After: 1`, `Cache-Control: no-store`로 응답한다.
  상태 조회의 `404`, 상태 충돌의 `409`, 복구 중 발급 차단의 `503`에도 캐시 저장 금지를 적용한다.
- 최신 취소와 시즌 이름을 함께 대조하는 복구 매니페스트·완료 요청의 고정 예시를 추가했다.
  실제 백업·복원 스모크에서 완료 응답을 확인한 뒤 복구 모드를 해제하도록 연결했다.

## 호환성과 사용 조건

기존 요청·응답 스키마와 iCalendar 골든 파일은 변경하지 않았다. 복구 진단용 응답 스키마 두 개와
예시를 추가했으며, `rc.1` 이후 새 DB 마이그레이션은 없다. 새 구독 PUT은 기존 생성 요청·응답 스키마를 사용한다.

구독 생성 응답을 잃으면 저장한 ID로 상태를 조회한다. `404`일 때만 같은 ID·시즌으로 PUT을 다시 보낸다.
활성 구독의 토큰을 받지 못했다면 사용자 요청에 따라 기존 rotate로 재발급한다. 토큰 원문은 다시 조회할 수 없고,
기존 POST 생성과 rotate를 응답 유실만으로 자동 재시도하지 않는다.

복구 진단 GET은 읽기 전용이다. 저장된 `COMPLETED`는 과거 검증 결과이며, 현재 데이터의 최신성을 보증하거나
복구 모드를 해제하지 않는다. CAL의 진단 값을 BATON의 기대 매니페스트로 대신 사용하지 않는다.

## 적용 순서

1. 후보 변경을 원격 `main`에 반영하고 필수 CI를 확인한 뒤, `contracts-v1.1.0-rc.2` 태그와
   `baton-cal-contracts-1.1.0-rc.2.zip`을 [릴리스 절차](../contract-release-procedure.md)에 따라 게시한다.
2. 모든 CAL 인스턴스를 새 PUT·GET을 지원하는 버전으로 전환한다. 일반 배포에서는 기존 구독 세대를 유지한다.
3. BATON에서 공식 태그·ZIP·SHA-256을 고정하고 릴리스·자산 증명을 검증한다. 생성 응답 유실·중복·시즌 충돌,
   상태 조회·재발급·폐기와 복구 진단을 실제 CAL에 대조한 뒤 새 경로를 활성화한다.

## 검증 상태와 남은 확인

2026-09-12의 `a242bc9` 코드에서 전체 테스트 141개·구조 테스트 3개와 계약 ZIP 검증을 통과했다.
실행 범위와 로그는 [인수인계](../../HANDOFF.md)에 기록했다. 이번 문서는 릴리스 게시나 BATON의 공식 자산 고정을 뜻하지 않는다.

공식 자산을 고정한 BATON 연동 검증과 실제 Google Calendar·Apple Calendar·Outlook의 구독·갱신·취소 확인은 남아 있다.
공개 HTTPS와 앱 계정을 준비한 뒤 [앱별 확인표](../calendar-subscription-guide.md)를 사용한다.
