# BATON CAL 계약 1.1.0-rc.1

`1.1.0-rc.1`은 BATON 생산자 연동 검토를 위한 사전 릴리스다. 현재 안정 기준 `1.0.0`을 자동으로
대체하지 않는다.

## 주요 변경 사항

- 128 KiB JSON 문서 상한에 필드명 64자, 중첩 16단계, 숫자 10자리와 토큰 256개 제한을 추가했다.
- UUID 입력을 하이픈이 있는 36자 표준 문자열로 고정하고 내부 Bearer 설정의 RFC 6750 형식을 검증한다.
- 공개 피드의 Last-Modified가 응답 Date를 넘지 않게 하고 강한 ETag 조건을 우선 판정한다.
- 취소 뒤 더 높은 개정 번호로 재활성화하는 일정 생명주기를 계약 예시로 고정했다.
- 예상 밖 `500`에서 내부 메시지를 숨기고 데이터베이스 제한 시간 초과를 `503 SERVICE_BUSY`와
  `Retry-After: 1`로 반환한다.
- iCal4j 4.3.0 내장 Olson `2025a`를 시간대 입력과 `VTIMEZONE` 규칙의 단일 권위로 사용한다.
- `prod` 데이터베이스 연결값이 로컬 기본값을 상속하지 않게 했다.
- 복구 모드에서 구독 생성·회전을 `503 RECOVERY_IN_PROGRESS`로 차단한다. 수신·재구축·폐기는
  유지하며, 운영자가 전체 재전달 완료를 확인한 뒤 모드를 해제한다. 완료 시각을 알 수 없으므로
  `Retry-After`와 생성·회전 자동 재시도는 추가하지 않는다.
- 내부 일정·구독 상태 조회를 추가했다. CAL이 채택한 일정의 개정 번호·상태·원본 수정 시각과
  구독 상태·현재 세대 일치 여부를 반환한다. 복구 모드에서도 사용할 수 있으며 토큰·해시·피드 URL과
  세대 UUID는 반환하지 않는다. 전체 재전달 완료 판단이나 유실된 토큰 복구 기능은 아니다.

BATON은 태그·자산·SHA-256을 고정하고 운영 직렬화기, 변경·취소·재활성화·중복·역순 전달과 실제
CAL 컨테이너 교차 서비스 테스트를 통과해야 한다. 의미 변경이 필요하면 이 자산을 교체하지 않고
다음 RC를 게시한다.
