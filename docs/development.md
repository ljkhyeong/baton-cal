# 개발 검증 절차

## 실행 전

- 현재 저장소·브랜치·미커밋 변경을 확인한다. 다른 작업 트리는 `git worktree list`로 확인하고,
  과거 작업에 적힌 경로를 현재 프로젝트 경로로 가정하지 않는다.
- [인수인계](../HANDOFF.md)의 최근 검증을 확인하고 이후 변경 파일을 `git diff <검증 커밋>`으로 비교한다.
  미추적 파일·의존성·설정·테스트 환경 변경도 포함한다. 커밋명이나 브랜치명만으로 재사용을 결정하지 않는다.
- 변경한 동작, 필요한 검증, 완료 조건을 정한다. 결과를 재사용하면 근거를 적고, 재실행은 입력 변경·실패·
  환경 차이·필수 CI 중 이유를 밝힌다. 입력을 확인할 수 없으면 해당 범위를 다시 검증한다.

## 검증 선택

| 변경 | 로컬 검증 |
| --- | --- |
| 문서·지시 | `git diff --check`, 바뀐 내용과 참조 경로 확인 |
| 스킬 | `./scripts/validate-skill.sh <스킬 디렉터리>` |
| 단일 기능 | `./gradlew --no-daemon test --tests '<관련 테스트 클래스>'` |
| HTTP·계약 | 관련 HTTP 응답의 JSON Schema 테스트, `./gradlew --no-daemon verifyContractsZip` |
| 공통 코드·여러 계층 | `./gradlew --no-daemon check` |
| DB 스키마 | 관련 저장소·마이그레이션 통합 테스트 |
| 이미지·운영 구성 | [README의 이미지 검증](../README.md#oci-이미지-검증), [운영 검증](operations.md#재현-가능한-로컬-검증) |
| 구독 세대·복원 | 실제 백업 복원, 과거 URL `404`, 최신 재전달·완료 후 새 발급 |
| BATON 연동·복구 다이제스트 | 요청 범위에서 BATON 실제 직렬화기와 CAL의 HTTP 교차 검증 |
| 성능 측정 | 목표·환경을 정한 뒤 [성능 기준](performance-baseline.md)의 부하 테스트 |

DB 통합 테스트에는 Docker가 필요하다. `check`는 일반 테스트와 계약 ZIP을 검증하며 부하 측정·이미지
빌드·운영 스모크는 포함하지 않는다. PR·공식 릴리스의 필수 CI는 로컬 검증과 별도로 완료한다.

## 재실행과 종료

- Gradle 캐시와 증분 검사를 사용한다. `clean`·`--rerun-tasks`는 기본 명령에 붙이지 않는다.
  새 성능 측정이나 캐시 문제 조사처럼 실제 재실행이 필요할 때 이유를 남긴다.
- `UP-TO-DATE`·`FROM-CACHE`는 기존 성공 결과 재사용으로 보고한다. 새 테스트 실행으로 쓰지 않는다.
  관련 입력·환경이 같은 단순 브랜치 이동이나 fast-forward 병합은 전체 재검증 이유가 아니다.
- 실패하면 제품 오류, 테스트 오류, 환경·도구 오류를 먼저 구분한다. 환경을 고치지 않은 채 같은 명령을
  반복하거나 원인 확인 전에 전체 테스트로 넓히지 않는다.
- DB·브라우저·이미지처럼 자원을 많이 쓰는 검증은 같은 장비의 다른 실행을 확인해 겹치지 않게 조정한다.
  시간 초과는 로그와 부하를 확인한 뒤 실패한 범위부터 재실행한다. 다른 작업의 프로세스를 임의 종료하지 않는다.
- 실패 로그와 결과 파일을 확인한 뒤 재실행한다. Gradle은 `build/test-results/test/`와
  `build/reports/tests/test/`를 사용한다. 필요한 범위가 통과하면 종료하고 변경·실패 근거 없이 확대하지 않는다.

인수인계에는 최신 관련 검증만 `기준 커밋·미커밋 여부 / 명령·범위 / 환경 / 실행·캐시 재사용 /
결과·제한`으로 기록한다. 과거 결과는 커밋과 검토 문서에 남기고 매 작업마다 완료 내역을 누적하지 않는다.

## 스킬 검증 환경

`validate-skill.sh`는 공통 지침의 `~/.codex/venvs/skill-validation/bin/python`을 사용한다.
검증기 위치는 `${CODEX_HOME:-$HOME/.codex}/skills/.system/skill-creator/scripts/quick_validate.py`다.

공용 환경이나 PyYAML이 없으면 다음 명령으로 준비한다. 이후에는 같은 환경을 재사용하며,
프로젝트별 가상환경을 만들거나 시스템 Python에 패키지를 설치하지 않는다.

```bash
python3 -m venv ~/.codex/venvs/skill-validation
~/.codex/venvs/skill-validation/bin/python -m pip install 'PyYAML==6.0.3'
```

| 이전 BATON 경로를 현재 프로젝트로 오인했고 인수인계는 217줄로 누적 | 현재 작업 트리 확인, 최신 검증과 남은 작업만 인계 |

필요한 충돌 해결 후 전체 테스트나 새 성능 측정은 낭비로 분류하지 않았다. 앱의 작업 조회에서 본문이
비어 있는 최근 기록은 동일 요청을 반복하지 않고 해당 CAL 작업의 로컬 기록으로 보완했다.
